Something went wrong

vdodtor never sends anything anywhere, including when it breaks. So a problem reaches us only if you send it — which is what opt-in means for an app with no socket to open.

Open an issue on GitHub Email it instead

What to include

  • The version, from vdodtor → About vdodtor. That line is selectable so it can be pasted.
  • What you were doing, and what happened instead.
  • The crash report, if there is one.

Finding the crash report

If vdodtor hits a fault it writes a report to your own disk and offers it on the chooser the next time you launch. You can also always read it in About vdodtor → Problem report, where there is a Copy button beside it.

The file itself is here, and it is plain text:

~/Library/Application Support/vdodtor/crash.txt

What has already been taken out of it

Every absolute path is replaced with <path> before the file is written, keeping only the extension — so <path>.mov survives and the names of your footage, and your account name, do not. There is no unscrubbed copy anywhere for anything to find later.

package: and dart: locations are kept, because those are ours and they are what makes a stack trace worth reading. Read the whole thing before you send it — that is rather the point of it being shown to you.

If the app quit without leaving a report

A fault deep in the video engine can stop the process before vdodtor gets a turn to write anything. macOS records those itself, and they are not in a place vdodtor is allowed to read:

~/Library/Logs/DiagnosticReports/

Look for the most recent file whose name starts with vdodtor. Those reports are Apple's rather than ours, so we have not scrubbed them — read one before sending it.
